# 24 — M30：多艦隊收尾（海圖標記＋跨艦隊通知）

> 補上 docs/23（M29 多艦隊管理）§4 刻意延後的兩項：海圖同時顯示多艦隊、
> 跨艦隊事件不再被靜默吃掉。

## 1. 海圖同時標出其他艦隊

`SeaMap.tsx` 原本是單一 PIXI 精靈/軌跡的渲染模型（`shipRef` 逐幀內插移動）。
沒有把這個模型直接擴充成多艘船的內插動畫（那是更大的渲染重構），而是新增一個
**獨立、不逐幀動畫**的圖層：

- 新增 prop `otherFleets?: { id, pos, name }[]`。
- 新增 `otherFleetsContainerRef`：一個獨立的 PIXI `Container`，跟主力艦隊的
  `ship`／`trail` 完全不共用邏輯。
- 新增一個只依賴 `[otherFleets]` 的 `useEffect`：每次這個陣列變動（也就是
  `snapshot` 更新時）就整層清空重畫——每支其他艦隊一個三角形標記＋名稱標籤，
  直接 `position.set()` 到目前座標，不做位移動畫。

`apps/web/src/app/play/[worldId]/page.tsx` 新增 `otherFleetMarkers`
（`useMemo`，排除目前選中的艦隊，其餘各自轉換 axial→offset 座標後傳入）。

**取捨**：其他艦隊的位置只在快照更新時才會跳到新位置（不平滑動畫），跟主力
艦隊「連續移動」的體驗不同——這是刻意的簡化，避免把單一精靈的渲染模型改成
以艦隊 id 為 key 的集合這種較大改動；日後如果需要多艦隊同時平滑移動，可以
在這個新圖層上疊加內插邏輯，不影響主力艦隊既有的渲染路徑。

## 2. 跨艦隊事件不再被靜默忽略

`page.tsx` 原本的 `SERVER_ARRIVAL`／`SERVER_EVENT` 處理常式，只要事件的
`fleetId` 不是目前選中的艦隊就直接 `return`——玩家在操作艦隊 A 時，艦隊 B
抵港或發生風味事件會完全沒有任何提示。

修法：

- 新增 `fleetsRef`（一個跟著 `snapshot` 更新的 ref，解決既有 WS handler
  「掛載時的 stale closure 讀不到最新 state」的老問題——這個模式與既有的
  `latestFleetRef` 完全一致）。
- `SERVER_ARRIVAL`：不是選中艦隊時，不去動屬於選中艦隊的過場/航程摘要狀態，
  改用一則輕量通知「『艦隊名』已抵達 XX」，畫面焦點不強制切換過去。
- `SERVER_EVENT`：同樣邏輯——事件屬於非選中艦隊時，通知文字掛上該艦隊名字
  （「『艦隊名』：事件敘事」），且不計入選中艦隊的航程事件計數、不觸發選中
  艦隊視角的風暴閃光特效（那是綁在「你正在看的海域」上的視覺效果）。
- `SERVER_BATTLE_START` 維持不變：不論哪支艦隊遭遇海賊，戰鬥畫面都照常彈出
  （這是 docs/23 已經記錄的既有行為，海戰本身不會被錯過）。

## 3. 測試

純前端改動，沒有新增後端邏輯，API/shared 測試維持原本的 20 個 suite／163 個
測試、23 個檔案／168 個測試不變。

真實環境端對端驗證（本機 Postgres + Redis + 真實 API/web server +
Playwright）：建立世界、造第二艘船分艦成立「巡邏艦隊」，切過去出港；切回
「第一艦隊」後，截圖確認海圖上正確顯示「巡邏艦隊」的三角形標記＋名稱標籤，
證明多艦隊位置確實會同時呈現在同一張海圖上。跨艦隊通知的文案邏輯（正確
查出對方艦隊名稱、不干擾選中艦隊狀態）以程式碼審閱確認正確；因隨機事件/
抵港本身需要較長航程與時間才會觸發，此部分主要靠檢視程式邏輯而非強行等待
即時事件發生。

`apps/web` `tsc --noEmit`、`next build` 皆通過。
